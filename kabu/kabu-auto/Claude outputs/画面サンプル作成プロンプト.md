# 他のAIに渡すプロンプト(そのままコピーして使えます)

以下の「ここから」から「ここまで」を、そのまま他のAIに貼り付けてください。

---------------------------------------- ここから ----------------------------------------

あなたは、業務ツールの画面デザインが得意なUIデザイナー兼フロントエンドエンジニアです。
日本の個人投資家向けの「株の自動売買ツール」の操作画面(ダッシュボード)の、見た目のサンプルを作ってください。

## 出力してほしいもの

- 1つのHTMLファイル(CSSとJavaScriptをすべてファイル内に書く。外部のライブラリ・画像・フォント・CDNは使わない)
- ブラウザで開くだけで表示できること
- グラフは、外部ライブラリを使わず、インラインのSVGで描く
- データは、すべてこちらが下に書いた「ダミーデータ」を、JavaScriptの中に直接書く(通信はしない。実在のAPIにはつながない)
- 画面上の文字は、すべて日本語
- 作ったあと、画面を1枚のスクリーンショットとして見せられる場合は見せる(できなければ、HTMLだけでよい)

## このツールは何か(前提)

- 個人のパソコンの中だけで動く、株の自動売買ツール。ブラウザで開く、自分専用の管理画面です。
- 1日1回の判断で売買します。戦略は「移動平均クロス」:短期(5日)の平均株価が、長期(25日)の平均株価を、下から上に抜けたら「買いシグナル」、上から下に抜けたら「売りシグナル」。
- 注文は、翌営業日の寄り付きに成行で出す想定です。
- 動作のモードは2つ。「ペーパー(発注しない・出したつもりで記録するだけ)」と「実発注」。**この画面は、ペーパーの操作・閲覧・検証だけができて、実際に注文を出す機能は持たない**、というのが大事な条件です。
- 使う人はプログラミングを知らない個人です。専門用語を避け、状態が一目で分かることを最優先にしてください。

## 画面の構成(ページは1枚。縦に、この順で並べる)

### 1. ヘッダー
- 左に、アプリ名「kabu-auto」
- その右に、モードのバッジ。ペーパーのときは緑系で「ペーパー(発注しない)」。実発注のときは赤系で「実発注モード」
- その右に、今日の日付と、営業日か休場日かの表示(例:「2026-09-19(休場日・土日)」)、接続先(「本番」または「検証環境」)
- 右端に「更新」ボタン

### 2. お知らせ(バナー)
状況に応じて出す帯。ふだんは何も出ない。次の3種類を作る(サンプルでは2つ出しておく)。
- 黄色の警告:「判定できていない日があります: 2026-09-16(8306)。データを取り直して『手元のデータで判定だけ』を押してください。」
- 黄色の警告:休場日ファイルに今年の分がない、というお知らせ(サンプルでは出さなくてよいが、作りは用意する)
- 赤い注意:「設定が実発注モードです。この画面のペーパー操作は止めています(閲覧と検証は使えます)。」(このときは下のペーパー操作のボタンが押せなくなる)

### 3. 数字のカード(横に5枚)
- 累積損益(確定):「+12,400円」(プラスは緑、マイナスはオレンジ系)
- 含み損益:「-77,738円」
- 保有銘柄:「1 件」
- 待ち注文:「1 件」
- 帳簿の更新:「2026-09-19 13:16:31」

### 4. 「保有中(帳簿)」と「明日以降の注文(待ち)」(2つの表を横に並べる。狭い画面では縦)
保有中の表の列:銘柄コード/株数/取得日/取得値/直近終値/含み損益
- 行の例:7203 / 100 / 2026-08-20 / 2,500.0 / 1,722.6 / -77,738円

待ち注文の表の列:日付/銘柄/売買/株数/理由/状態
- 行の例:2026-09-24 / 6758 / 「買い」(緑のタグ) / 100 / 2026-09-18 ゴールデンクロス / 未送信
- 「売り」のタグはオレンジ系
- 状態は「未送信」「送信済み」「結果不明・要確認」「見送り・失敗」のどれか

### 5. 「要確認: 約定扱いにしなかった注文」(該当があるときだけ出る表)
- 列:日付/銘柄/売買/株数/理由
- 行の例:2026-09-10 / 9432 / 買い / 100 / 発注していない(失敗か、1日の上限超過)

### 6. 「銘柄とデータ」(表。行をクリックすると下のチャートが切り替わる。選んだ行は薄く強調)
列:銘柄/行数/期間/直近終値/直近のシグナル/位置/データの状態
- 7203 / 444 / 2025-01-06 〜 2026-09-17 / 1,722.6 / - / 短期が下 / OK
- 6758 / 444 / 2025-01-06 〜 2026-09-17 / 3,726.2 / 「買い」タグ / 短期が上 / OK
- 9432 / 444 / 2025-01-06 〜 2026-09-17 / 103.0 / - / 短期が下 / 「段差 2026-08-03 に前日比 0.52 倍」(赤いタグ)
- 8306 / 0 / - / - / - / - / 「データなし」(赤いタグ)
- 「データの状態」は、OK/少ない/段差あり/データなし、の4種類

### 7. チャート
- タイトル:「チャート 6758」(選んだ銘柄のコード)
- 折れ線グラフ(SVG)。約250日ぶん。3本の線:終値(細い濃い線)、短期5日の移動平均(青)、長期25日の移動平均(オレンジ)
- 売買シグナルを、線の上にマークする:買いは緑の上向き三角(▲)、売りはオレンジの下向き三角(▼)
- 縦軸に価格の目盛り(横線つき)、横軸の左端と右端に日付
- グラフの下に凡例:終値/短期 5日/長期 25日/▲買いシグナル/▼売りシグナル/(直近 250 日)
- 終値は、ゆるやかに上下しながら、ときどき短期線が長期線を上下に抜けるように、ダミーの動きを作る(移動平均線は、終値から本当に計算して描くこと)

### 8. 累積損益の推移(帳簿)
- 折れ線グラフ(SVG)。横軸は日付(2026-06-01〜2026-09-17)、縦軸は累積損益(円)
- 0円の位置に点線の横線。最大値(例 15,900)と最小値(例 -2,000)の目盛りを出す
- 記録が1件もないときは「まだ記録がありません」と表示する作りにする

### 9. 「ペーパーの操作」と「検証とデータ」(2つのパネルを横に並べる。狭い画面では縦)
ペーパーの操作(パネルの説明文:「発注しないモードで、収集と判定・朝の確認をします。実発注はこの画面ではできません。」)
- ボタン3つ:「今日の収集と判定」(主ボタン・目立つ色)、「手元のデータで判定だけ」、「朝の確認」
- 実発注モードのときは、この3つが押せなくなる(薄く表示し、押せない状態)
- ここに「実際に注文を出す」ボタンは作らない

検証とデータ
- 銘柄の選択(プルダウン。例「7203(444行)」)
- チェックボックス2つ:「walk-forward」(初期でオン)、「総当たり(罠の実演)」(初期でオフ)
- ボタン:「バックテスト」(主ボタン)、「データの点検(全銘柄)」
- 区切り線のあと、「過去データ(CSV)の取り込み」:銘柄コードの入力欄(例 7203)、ファイル選択、「取り込む」ボタン
- 取り込みの結果を、入力欄の下に小さく出す(例:「7203: 250 行を取り込みました。」「注意: 調整後の列を使いました…」「警告: 6758: 2026-08-03 に前日比 0.52 倍の段差…」)

### 10. 「実行結果」
- 上のボタンを押したあとの、実行状況と結果の文字を出す欄
- 状態の表示:「実行中…」→「終了しました(正常)」または「終了しました(終了コード 1。上の出力を確認してください)」
- 出力は、等幅フォントの黒っぽい枠(スクロールできる)に表示する。サンプルとして、バックテストの結果を入れておく:
  - 銘柄 7203  2025-01-06 〜 2026-09-17(444 日)
  - 約定: シグナルの翌営業日の寄値 / コスト 片道 10bp(税金は下に概算で別表示)
  - 素直 5日/25日: 累積損益 -393.8円(1株)/ 取引 12 回 / 勝率 8.3% / 1取引あたり平均 -1.55%
  - 　税引後(概算・確定した取引のみ): -400.6円 / 税 6.9円(税率 20.315%。繰越控除・損益通算は考えない)
- 実行中は、ほかのボタンを押せなくする

### 11. 一番下に、「設定(読み取りのみ)」と「ログ(末尾)」(2つを横に並べる。狭い画面では縦)
設定の表(項目と値の2列):
- 移動平均(短期/長期):5日 / 25日
- 1回の買いの上限金額:500,000 円
- 1日の発注上限:3 件
- 対象銘柄:4 銘柄
- バックテストのコスト(片道):スリッページ 10bp + 手数料 0bp
- 税率(概算表示):20.315%
- 「設定はここでは変更できません」と分かるようにする(入力欄にしない)

ログ:等幅フォントの小さな枠。例:
- 2026-09-19 13:16:31　--- 2026-09-16 引け後の処理 ---
- 2026-09-19 13:16:31　　新しいシグナルはありません
- 2026-09-19 13:16:31　　[WARN] 8306: 2026-09-16 の終値が無い(データ収集が失敗?)。判定を飛ばします

## 動きのこと(サンプルでも実際に動くようにする)

- 「銘柄とデータ」の行をクリックすると、チャートの銘柄が切り替わる(銘柄ごとに、別のダミーの株価データを用意する)
- 「更新」ボタンを押すと、「更新しました」のような軽い表示が出る
- 「バックテスト」などの実行ボタンを押すと、(実際には何も動かさず)「実行中…」を2秒ほど見せてから、「終了しました(正常)」と結果の文字を出す。ボタンは、実行中は押せない
- 画面の右上か、ヘッダーに、確認用の切り替えスイッチを置く(本番の機能ではなく、サンプルを見比べるためのもの):
  - 「モード: ペーパー/実発注」の切り替え → 実発注にすると、赤いバナーが出て、ペーパー操作のボタンが押せなくなる
  - 「データ: あり/なし」の切り替え → なしにすると、表とグラフに「まだ記録がありません」などの空の表示が出る
  - 「表示: ライト/ダーク」の切り替え

## デザインの方針

- 落ち着いた、業務ツール向けの見た目。派手にしない。余白を十分にとり、文字は読みやすく(基準の文字サイズは15px前後)
- 色の意味は固定にする:緑=プラス・買い・正常/オレンジ=マイナス・売り/黄=注意/赤=危険・要確認/青=主な操作ボタン・短期線
- 損益の色は、色だけに頼らず、「+」「-」の記号も必ず付ける
- ライトとダークの両方に対応する(OSの設定に合わせて自動で切り替わる。上の切り替えスイッチでも変えられる)
- パソコン幅(約1100px)を基準にしつつ、スマホ幅(約390px)でも、横にはみ出さないこと。表は、はみ出すときだけ横にスクロールさせる
- 見出しはカードの中に小さく。カードは、白(ダークでは濃い紺)の背景に、薄い枠線、角丸10px程度
- 数字は右揃えで、桁がそろう(等幅の数字)

## 守ってほしい条件(大事)

- 実際に注文を出すボタン、「買う」「売る」「発注」という名前の操作は、画面のどこにも作らない
- 実在の証券会社・銀行・企業のロゴや、投資の勧誘に見える文言は入れない。ダミーデータであることが分かるよう、ページの一番下に小さく「これはサンプル画面です。数字はすべてダミーです。」と入れる
- 個人情報や、パスワード・APIキーを入力させる欄は作らない
- 「銘柄コード」は、4桁の数字か英数字。ダミーとして、7203・6758・9432・8306 を使ってよい(会社名は表示しない)

## 使い方のメモ(あなた向け・AIには貼らないでください)

- 画像で仕上がりを見たいときは、画像を出せるAI(またはHTMLをプレビューできるAI)に貼ってください。HTMLしか返ってこないAIの場合は、返ってきたHTMLを「〇〇.html」という名前で保存して、ブラウザで開くと見られます。
- 出来上がった画面と、いまのkabu-autoの画面は、機能の並びを合わせてあります。他のAIの案の中で「いいな」と思った部分(配色、カードの形、グラフの見せ方など)だけを、こちらに持ってくることもできます。その案の画像かHTMLを、こちらに送ってください。
