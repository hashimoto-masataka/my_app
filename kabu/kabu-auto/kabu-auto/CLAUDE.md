# このプロジェクトについて

三菱UFJ eスマート証券の kabuステーションAPI を使う、株の自動売買プロジェクト（『Claude Codeで作る株の自動売買入門』の完成パッケージ）。
判断は日足ベースで1日1回。戦略は移動平均クロス（config.py の SHORT_PERIOD / LONG_PERIOD）。
実際の発注は行わない（発注しないモードで運用中。config.py の ORDER_MODE = "paper"）。

# 参照

- API仕様とエラーコードの意味は docs/ 内の資料を参照する。記述が食い違うときは docs/kabu_STATION_API.yaml を正とする。
- 設定は config.py が唯一の正本。コードに数字を直書きしない。

# 必ず守ること

## 認証・接続
- APIパスワードは環境変数 KABU_API_PASSWORD から読む。コードに直書きしない。ログにも出さない。
  パスワードの中身をチャットに書かない（有無や文字数の確認はよいが、値そのものは表示しない）。
- あとから設定した環境変数は、開いているアプリや画面には反映されない。読めないときは、アプリの再起動を試す。
- APIの実体は kabuステーション（Windowsアプリ）。アプリが起動・ログインしていないと接続できない。
  「接続できない」時はまずアプリの状態（右上の「</>」が緑か）を疑う。
- 毎朝6:15にAPIのトークンが失効する（アプリの窓は開いたまま。6:30以降の再ログインで復帰）。失効する前提で書く（kabu_auto/api.py は毎回取り直す）。
- トークンは新規発行すると既存のものが無効になる。プログラムを同時に複数起動しない。
- 接続できないときはログに残して終了する。無限にリトライしない（メンテナンス・障害の日に暴走しないため）。

## API制限
- 情報系のリクエストは1秒あたり10件程度が上限。連続で叩くときは待ち時間を入れる（api.py の REQUEST_INTERVAL）。
- 銘柄登録リストの上限は合計50銘柄。RESTでデータを取得しただけでも自動登録され枠を消費する。
  収集の最後に unregister_all() で解除する。対象銘柄（config.SYMBOLS）は20〜30までにする。
- 同一銘柄に対する注文は5件が上限。

## データ
- 株価データは実データのみを使う。取得できない場合、ダミーデータやサンプルデータを生成して代替してはいけない。
  取得できないなら「取得できない」と報告すること。
- 日足は data/daily/{code}.csv（Date,Open,High,Low,Close,Volume）。入手先が違っても、この列名に揃える。
- 株式分割に注意する。前日比で±40%を超えたら暴落と決めつけず分割・併合を疑う（data.py が警告を出す）。
  直近 LONG_PERIOD 日にそういう段差がある銘柄は、新規の買いシグナルを出さない（paper.make_signals）。保有中の売りは止めない。
- 板情報の値は「最後に付いた値」。現値時刻（CurrentPriceTime）の日付が今日でなければ、今日の終値として貯めない（data.append_today）。
- 休場日ファイル（data/holidays.txt）にその年の分が無いときは、実発注しない（paper.morning）。カレンダーを勝手に推測で作らない。
- 調整後株価（AdjC など）を取り込むと、今日から貯める未調整の値と段差ができうる。取り込み後は `py run_backtest.py --audit` で点検する。
- 取引時間外に取得した「現在値」は最後に付いた値（前日の大引け）。時刻が前日15:30なら正常。

## 使う人への配慮
- ユーザーはプログラミングの前提知識なしで進めている。エラーメッセージは日本語で、
  原因の見当（kabuステーション未起動／パスワード違い等）まで表示する。
- 画面に出す文字列に全角のダッシュ「—」を使わない（Windows のコンソールで落ちる）。
- 日本語を含む .ps1 は BOM 付き UTF-8 で保存する。bat の中身は半角英数字だけにする。

## 安全（変更禁止）
- 発注処理は既定で無効（ORDER_MODE = "paper"）。実発注は ORDER_MODE = "live" のときだけ動作させ、
  有効時は起動時に警告を出すこと（run_morning.py）。
- ORDER_MODE を "live" に変えるのは、ユーザーが「実発注モードに切り替えて」と明示的に頼んだときだけ。
  自分の判断で変えない。変えたら、その旨を必ず報告する。
- 注文は翌営業日の寄り付きの成行（FrontOrderType=13）。1日の発注件数は DAILY_ORDER_LIMIT を超えない。
- 買いの株数は sizing.order_qty（config.BUDGET_PER_ORDER に収まる最大の単元数）で決める。株数を直書きしない。
  1単元が上限を超える銘柄は買わずに見送る（ログに出る）。単元が100株でない銘柄は config.LOT_SIZES に書く。
- バックテストは実運用と同じルール（シグナルの翌営業日の寄値で約定・片道コスト込み）に保つ。当日の終値で約定させない。
- 注文の市場は SOR（Exchange=9）。東証（1）を指定した現物の新規注文は「100378 現物買・売注文抑止エラー」で拒否される
  （仕様書の Exchange 欄「通常時に東証を指定しての新規発注はできません」）。板情報の取得は東証（@1）でよい。
- 画面（run_gui.py / kabu_auto/webui.py / webui.html）から発注できるようにしない。発注の関数（send_order・cancel_order）も `--mode live` も、
  画面のコードに書かない（tests/test_webui.py が確かめる）。画面は 127.0.0.1 だけで待ち受け、操作には起動ごとのトークンを要求し、
  ペーパーの操作は config.ORDER_MODE が "paper" のときだけ動かす（run_collect.py / run_morning.py も、画面から呼ばれて live なら断る）。
- 注文と取消を短時間に繰り返す作りにしない（相場操縦と疑われる。第7章 7-1）。
- 注文の送信（api.send_order）はリトライしない。応答が届かなかっただけで受理済み、ということがあり、再送すると二重注文になる。
  結果が分からないときは api.OrderUncertain。再送せず、注文約定照会で人が確認する。
- 朝の発注（paper.morning）は、同じ日に何度実行しても二重に出さない（送信済みの注文には order_id が付く）。売りを先に出す。
- paper.morning / paper.evening は state/account.lock で排他する（朝のボタンの2度押しで同じ注文を2回出さない）。
  朝の発注は1件送るごとに state を保存する（途中で止まっても、送った注文の order_id が残り、再実行で再送しない）。
  この2つを外さない。d より前の日付の注文は期限切れとして unfilled に移す。約定0株の注文は建玉として記帳しない。
- 実発注の朝は、発注の前に証券会社の残高（api.holdings＝読み取りだけ）と突き合わせる。すでに保有がある銘柄は買わず、足りない売りは出さない。
  残高を取れないときは実発注を止める。引け後にも帳簿と残高を突き合わせ、食い違いをログに出す（何も書き換えない）。
  トークンは新しく取ると前のものが無効になるので、live_tools() のように1つを使い回す。
- 実発注モードの帳簿は、実際に発注に成功した注文だけを約定扱いにする（失敗・上限超過・結果不明は state の unfilled へ）。
  引け後は注文約定照会の約定数量で確かめる。この安全策を外さない。テスト: `py -m unittest discover -s tests`
- 発注できるコードは、このパッケージの中だけ（api.send_order を呼ぶのは start.py と run_morning.py）。
  試し撃ち用の別スクリプトを作らない。作ってしまったら、その場で消す（どこから飛んだ注文か分からなくなる）。
- 試し撃ち（start.py の t）は「受け付けられるか」の確認だけ。帳簿に手で1件積み、朝と同じ paper.morning で送る。
  出したら即取り消す。取引時間中はやらない。手で積んだ分は帳簿に残さない。
- start.py を実弾モードで走らせるときの `--confirm <合言葉>` は、ユーザーがそのメッセージで合言葉を書いたときだけ付ける。
  自分の判断で付けない。合言葉は config.CONFIRM_WORD（既定「実弾」）。
- 「合言葉を変えて」「合言葉を外して」と頼まれたら config.CONFIRM_WORD を変える。外す（空にする）ときは、
  うっかりで本物の注文が飛ぶ旨を一言添える。
