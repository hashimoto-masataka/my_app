# kabu-auto —— 本書の完成パッケージ

本書（『Claude Codeで作る株の自動売買入門』）で作るものを、ひとまとめにした完成形です。
第2章〜第7章の成果物がこのフォルダに全部入っています。**このフォルダを丸ごと作業フォルダにして、
Claude Code の「ローカル」で開いてください**（図2-1）。

- 戦略は第4章の移動平均クロス（短期5日／長期25日）。**この数字を「最適化」しないでください**（第6章）
- 発注は**既定で無効**（`ORDER_MODE = "paper"`）。実発注は 7-1b の手順を踏んでから
- kabuステーションAPI の癖（6:15のトークン失効・登録上限50・10件/秒）は組み込み済み（`CLAUDE.md`）

## 起動の仕方 —— `start.bat`

ダブルクリックすると、最初にモードを選ぶメニューが出ます。

```
  1) バックテスト              過去データで戦略を試す。kabuステーションは使わない
  2) 発注しないモード（ペーパー）  今日の収集と判定。注文は「出したつもり」で記録するだけ
  3) 実弾モード（実発注）        寄り付きの成行で、本当に注文を出す ★お金が動く
  s) 状態を見る    q) やめる
```

3) を選ぶと合言葉「実弾」（`config.py` の `CONFIRM_WORD`。変えられる。空にすると合言葉なし＝おすすめしない）を打つまで先に進みません。ここで選んだモードは**その1回だけ**で、`config.py` の
`ORDER_MODE` は変わりません（タスクスケジューラの `run_collect.bat`／`run_morning.bat` は config の設定で動く）。
コマンドで直接指定もできます：`py start.py --mode backtest 7203 --walk`。

## 画面で操作する —— `gui.bat`

`gui.bat` をダブルクリックする（Mac などでは `python3 run_gui.py`）と、ブラウザで操作画面が開きます。**このPCの中だけ**で開ける画面です（127.0.0.1）。

- 見る：保有・待ち注文・累積損益・銘柄ごとのデータの状態と直近シグナル・チャート（終値と移動平均・売買シグナル）・設定・ログ
- 検証：バックテスト（素直／walk-forward／総当たり）、データの点検、過去データ（CSV）の取り込み（UTF-8・Shift-JIS どちらも可）
- ペーパー：「今日の収集と判定」「手元のデータで判定だけ」「朝の確認」
- **実発注はこの画面からはできません。** 実弾は、これまでどおり `start.py` から（合言葉つき）。`config.py` が実発注モードのときは、ペーパーの操作ボタンを止めます（帳簿を壊さないため）
- 「収集」には kabuステーション（Windows）が要ります。Mac では、閲覧・検証・CSV の取り込みが使えます

## 1日の流れ

| いつ | 何を | どうやって |
|---|---|---|
| 朝 6:30〜 | kabuステーションにログイン（人の仕事） | 手で |
| ログイン直後 | 接続確認。帳簿に今日の注文があれば、実発注モードなら寄成で出す（発注しないモードなら「出したつもり」を表示） | `run_morning.bat`（デスクトップの「朝いちばんに押す」） |
| 16:00 | 今日の四本値を貯める → 今朝の注文を寄値で約定扱い → シグナル判定 → 明朝の注文を帳簿へ | `run_collect.bat`（タスクスケジューラで自動） |
| いつでも | バックテスト | `run_backtest.bat 7203 --grid --walk` |
| いつでも | データの点検（段差・欠け） | `py run_backtest.py --audit`（銘柄を付けなければ全銘柄） |

## 最初にやること

1. `password_setup.bat` をダブルクリックして APIパスワードを保存（第2章 2-3）。Claude Code を開き直す
2. `config.py` の `SYMBOLS` を自分の対象銘柄にする（**20〜30まで**。登録上限50の壁）。あわせて `BUDGET_PER_ORDER`（1回の買いの上限金額）を自分の資金に合わせる。単元が100株でない銘柄は `LOT_SIZES` に書く
3. 過去の日足を入れる（第5章）：J-Quants や yfinance で取った CSV を
   `py run_backtest.py --import 7203 取ってきた.csv` で取り込む（列名の違いは自動で吸収）
4. `data/holidays.txt` に今年の東証の休場日を書く（Claude Code に頼めばよい）。**その年の分が無いと、実発注は止まります**（祝日に注文を出さないため）。年が変わる前に、来年の分を足す
5. `run_collect.bat` を平日16:00にタスクスケジューラへ登録（第5章 5-5）

## 実発注に進むとき（7-1b）

順番はこうです。**発注できるコードは、このパッケージの中だけ**にしてください（試し撃ち用の別スクリプトを作らない。
どこから飛んだ注文か分からなくなります）。

1. 準備：最小単元ぶんの買付余力を入金する／kabuステーションのソフトリミット（1-4）を最小にする／規約を読む
2. **試し撃ち**（引け後に、Claude Code に走らせる）：

   ```
   py start.py --mode live t 9432
   ```

   合言葉を打つと、帳簿に 1銘柄・1単元の買い注文を手で1件積み、**朝のボタンと同じ処理**（`paper.morning`）で
   寄成を送ります。受け付けられたら**その場で取り消し**、注文約定照会で「約定 0 株」を確かめて終わります。
   お金は動きません。取引時間中（9:00〜15:30）は動きません。本番のシグナルが翌朝たどるのと同じ道を通す確認です。
   エラーが出たら、Claude Code に「docs/ の仕様書を正として原因を探して」と頼んでください
3. kabuステーションの「注文約定照会」に、受付と取消の2行が残っているのを自分の目で見る
4. 本当に出す日が来たら、Claude Code に「実発注モードに切り替えて」と頼む → `config.py` の `ORDER_MODE` が `"live"` になり、
   翌朝の `run_morning.bat` が寄り付きの成行注文を出します。最初は1銘柄・最小単元で。`DAILY_ORDER_LIMIT` が暴走の最後の砦です
5. 数日回して、7-2 のコスト（スリッページ）を実測と突き合わせる

注文の市場は **SOR（`ORDER_EXCHANGE = 9`）** です。東証（1）を指定すると「100378 現物買・売注文抑止エラー」で拒否されます（仕様書どおり。手数料無料化の条件も SOR 選択）。試し撃ちで実際にこのエラーを踏んで直しました（2026-09-03）。
