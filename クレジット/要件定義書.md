# クレジット利用明細集計アプリ 要件定義書

- 版: 1.4
- 作成日: 2026-09-05
- 対象: MVP（初期リリース）
- 確認資料: `ご利用内訳明細_キャッシングご返済明細_20260710.csv`

## 1. 目的

毎月作成されるクレジットカード利用明細のCSVファイルを読み込み、請求対象月ごとに整理して保存し、利用者ごと、かつ利用店名ごとに利用金額を合算して確認できるアプリを提供する。

集計結果は「利用者」「利用店名」「金額」の3項目で表示し、同じ利用者・同じ利用店名の明細が複数ある場合は1行にまとめる。

読み込んだ個別明細はアプリ上で確認し、不要な明細を集計対象から削除したり、削除した明細を復元したりできるようにする。操作後の月別集計は直ちに再計算する。

## 2. 添付CSVの確認結果

添付CSVを読み取り専用で確認した結果は次のとおりである。個人名、カード番号、個別明細の内容は本書に記載しない。

| 項目 | 確認結果 |
| --- | --- |
| 文字コード | UTF-8（BOM付き） |
| 区切り形式 | カンマ区切り、各項目はダブルクォート対応 |
| 利用明細の列数 | 10列 |
| 集計対象の通常明細 | 85件 |
| 利用者 | 2名 |
| 利用店名 | 全利用者合計で31種類 |
| 集計後の「利用者 × 利用店名」 | 35組 |
| 複数明細を合算する組 | 11組 |
| 利用明細以外の行 | タイトル、列見出し、利用者別小計、総合計、キャッシングご返済明細 |

上記の件数は添付CSVに対する受入確認値であり、プログラムの固定値にはしない。

## 3. 入力・保存・表示項目

アプリ上の項目とCSV列の対応は次のとおりとする。

| アプリ上の項目 | CSV列 | 用途 |
| --- | --- | --- |
| 利用者 | `名前` | 表示および利用者単位の集計キー |
| 利用店名 | `利用店名` | 表示および店舗単位の集計キー |
| 金額 | `利用金額` | 合算対象 |

月別管理および明細操作のため、次の項目もアプリ内部で保持する。

| 項目 | 取得元 | 用途 |
| --- | --- | --- |
| 対象月 | CSV読込時に利用者が確認・指定 | 月別の保存キー。`YYYY-MM`形式で保持 |
| 利用年月日 | CSVの`ご利用年月日` | 個別明細の識別補助および明細管理画面での表示 |
| 明細ID | アプリで生成 | 明細の削除・復元対象を一意に識別 |
| 集計状態 | アプリで生成 | `集計対象`または`削除済み` |
| CSVレコード番号 | CSV解析時に生成 | 読込警告および元レコードの識別補助 |
| 取込ファイル識別子 | ファイル内容から生成 | 同じCSVの重複取込防止 |

`カード番号`、`カード種別`、`支払い金額`、`支払区分`、`今回回数`、`摘要`は保存および集計結果表示の対象にしない。

## 4. 対象範囲

### 4.1 対象機能

- CSVファイルの選択およびドラッグ＆ドロップ
- CSV形式と必須列の検証
- 利用明細セクションの通常明細だけの抽出
- 「利用者 × 利用店名」単位の金額集計
- 利用者別合計の計算
- 集計結果、読込件数、除外件数、エラー・警告の表示
- 対象月を指定したCSVの保存
- 保存済み月の一覧表示と月の切替
- 月ごとの集計結果および個別明細の表示
- 個別明細の削除、複数選択削除、削除済み明細の復元
- 明細操作後の月別集計の再計算と保存
- 同一CSVの重複取込防止

### 4.2 MVPの対象外

- キャッシングご返済明細の集計
- 明細の利用者名・利用店名・金額・利用年月日の直接編集
- 明細の手入力追加
- 複数月を合算した期間集計、年次集計、比較グラフ
- 同一対象月に複数CSVを追記して合算する機能
- 月全体を削除する機能
- CSV、Excel、PDF等への結果出力
- 店名の手動統合ルール管理
- 分割払い、手数料、利息、税額の再計算
- ユーザー認証、クラウド同期、外部サービス連携

## 5. CSV読込要件

1. 1回の操作で1ファイルを読み込めること。
2. 拡張子 `.csv` のUTF-8およびUTF-8 BOM付きファイルに対応すること。
3. 改行、ダブルクォート、項目内のカンマをCSV仕様に従って解析すること。単純な文字列分割は使用しないこと。
4. 列番号ではなくヘッダー名から `名前`、`利用店名`、`利用金額` を特定すること。
5. 必須列の順番や他の任意列の有無が変わっても、必須列が一意に特定できれば読み込めること。
6. タイトル行や空行がヘッダーより前に存在しても、必須列を含むヘッダー行を検出できること。
7. CSV内の文字列はすべてデータとして扱い、命令、HTML、数式、プログラムとして実行しないこと。
8. ファイル上限は10MBまたは10万明細のいずれか先に到達する値とする。
9. CSV読込時に対象月を必須入力とする。対象月はカード利用日ではなく、そのCSVが表す請求・明細の月とする。
10. ファイル名に8桁の日付が含まれる場合は、その年月を対象月の初期値として提示する。ただし自動確定せず、利用者が確認または変更してから保存する。
11. 対象月は`YYYY-MM`形式で内部保持し、画面上では`YYYY年M月`形式で表示する。
12. ファイル内容から識別子を生成し、同一内容のCSVがすでに保存されている場合は重複取込を中止して通知する。
13. 同じ対象月に異なるCSVが保存済みの場合は、既存データを置き換えるか取込を中止するかを利用者に選択させる。自動追記は行わない。
14. 置換を選択した場合は、対象月、既存明細件数、新規明細件数を表示して確認を得た後に保存する。
15. CSV全体の検証が成功してから対象月のデータを保存し、エラー時に一部のデータだけを残さないこと。

## 6. 集計対象行の判定

1. `名前`、`利用店名`、`利用金額`を含む利用明細ヘッダーを検出し、その次のレコードから走査を開始する。
2. 次をすべて満たすレコードを通常明細とする。
   - `名前`が空欄ではない。
   - `利用店名`が空欄ではない。
   - `利用金額`が有効な整数金額である。
3. 1件以上の通常明細を検出した後、次のいずれかに到達した時点で利用明細セクションを終了する。
   - `キャッシングご返済明細`等、別セクションのタイトルを検出した。
   - 別の列見出しを検出した。
   - 完全な空行ではなく、`名前`と`利用店名`がともに空欄で、`ご利用年月日`列が存在する場合は同列も空欄であり、かつその他の列のいずれかに小計等の非空値があるレコードを検出した。
4. 完全な空行は読み飛ばし、次のレコードの走査を継続する。
5. セクション終了後の利用者別小計、総合計および別セクションは、警告対象にせず読み飛ばす。
6. セクション終了前に通常明細の一部の条件だけを満たすレコードは、不正な通常明細として警告対象にする。
7. 次の行は集計対象外とする。
   - タイトル行
   - ヘッダー行
   - 空行
   - 利用者別小計行
   - 総合計行
   - `キャッシングご返済明細`以降の別セクション
8. 個人名、店舗名、明細件数、列数など、特定ファイルの値を固定して行種別を判定しないこと。
9. 同一内容の通常明細が複数行存在しても重複エラーにはせず、各行を合算対象に含めること。
10. 別セクションの列数や金額欄が利用明細に似ていても、利用明細として取り込まないこと。

## 7. データ正規化

### 7.1 利用者と利用店名

- 先頭・末尾の空白を除去する。
- 改行等の表示に不要な制御文字を除去する。
- 正規化後の文字列が完全一致する場合だけ同一値として扱う。
- 全角・半角、英字の大小、内部空白、支店名、決済手段を示す接尾辞などは自動統合しない。
- 表示名は正規化後のCSV値を使用し、敬称等を自動削除しない。

### 7.2 金額

- `利用金額`を集計元とする。
- 前後空白、先頭の`¥`または`￥`を除去した後、符号付き整数として厳密に解析する。
- 3桁区切りカンマは正しい位置にある場合だけ許可する。小数、指数表記、途中までしか数値として読めない文字列は受け付けない。
- マイナス金額は返品・取消等の調整額として符号付きのまま集計する。
- 金額計算には整数型または同等の正確な数値表現を使い、浮動小数点誤差を発生させない。
- MVPで扱う個別金額および全集計値の範囲は、`-9,007,199,254,740,991`から`9,007,199,254,740,991`までとする。加算の途中も含め、この範囲を超えないことを検証する。
- アプリ側で消費税、手数料、為替換算は計算しない。

## 8. 集計仕様

選択中の対象月を `m`、正規化後の利用者を `u`、利用店名を `s`、各通常明細の利用金額を `a` とする。

```text
店舗別合計(m, u, s) = 対象月 = m、利用者 = u、利用店名 = s、集計状態 = 集計対象である全明細の a の総和
利用者別合計(m, u)  = 対象月 = m、利用者 = u、集計状態 = 集計対象である全明細の a の総和
月別合計(m)          = 対象月 = m、集計状態 = 集計対象である全明細の a の総和
```

- 集計キーは「対象月 × 利用者 × 利用店名」とする。
- 同一利用者・同一利用店名の複数明細は1行にまとめる。
- 同じ利用店名でも利用者が異なる場合は別の集計行にする。
- 同じ利用者・同じ利用店名でも対象月が異なる場合は別の集計とする。
- 利用者別合計は、その利用者の店舗別合計を再合算した値と一致すること。
- 月別合計は、その月の利用者別合計を再合算した値と一致すること。
- CSV内の小計・総合計は加算対象にしない。
- `削除済み`の明細は店舗別合計、利用者別合計、月別合計のすべてから除外する。
- 削除済み明細を復元した場合は、該当するすべての合計に再び含める。
- 削除または復元後は、影響する店舗別合計、利用者別合計、月別合計を即時に再計算する。
- 添付CSVでは`利用金額`と`支払い金額`は全通常明細で同額だが、将来異なる場合も`利用金額`を使用する。

### 8.1 保存単位

- 対象月を月データの一意キーとする。
- 月データには対象月、元ファイル名、ファイル識別子、取込日時、正常取込件数、警告件数を保持する。
- 個別明細には明細ID、対象月、利用年月日、利用者、利用店名、利用金額、CSVレコード番号、集計状態、削除日時を保持する。
- 明細IDは同じ月の中で一意とし、削除・復元後も変更しない。
- 店舗別、利用者別、月別の合計は、保存済み明細から再計算可能な派生データとする。
- 同じ対象月を置換する場合、既存の月データと明細を新しい取込結果で一括置換する。

## 9. 画面・表示要件

### 9.1 月別一覧・月切替

- 保存済みの対象月を新しい月から順に表示する。
- 月の表示形式は`YYYY年M月`とする。
- 各月に、集計対象の明細件数と現在の月別合計を表示する。
- 月を選択すると、その月の集計結果と明細管理画面を表示する。
- 初期表示では、保存済みデータがある場合は最新月を選択する。
- 保存済みデータがない場合は、CSV読込を案内する空状態を表示する。
- 選択中の対象月を画面上で明確に示す。

### 9.2 CSV読込領域

- 「CSVを選択」ボタンを表示する。
- ドラッグ＆ドロップでも選択できるようにする。
- 選択したファイル名を表示する。
- 対象月の入力欄を表示し、保存前に確認できるようにする。
- 読込中は処理中であることを表示し、二重実行を防止する。

### 9.3 読込結果

- 正常に取り込んだ明細件数を表示する。
- 除外した行数と、警告対象の行数を表示する。
- 致命的エラーがある場合は集計結果を表示しない。
- 警告がある場合は、結果が一部の正常行だけを対象としていることを明示する。
- 正常保存後は保存した対象月を選択し、その月の集計結果を表示する。

### 9.4 月別集計結果表

結果表の列は次の3列とする。

| 利用者 | 利用店名 | 金額 |
| --- | --- | ---: |
| CSVの名前 | 集計した店舗名 | `1,234円`形式 |

- 利用者ごとに店舗別の集計行を表示する。
- 集計結果表の上部に利用者ごとの合計金額を明示する。
- 利用者ごとの合計金額には`集計対象`の明細だけを含め、`削除済み`の明細を含めない。
- 各利用者の末尾に利用者別合計行を表示し、利用店名欄は`合計`とする。
- 初期表示順は、利用者を文字列昇順、同一利用者内では金額の降順、同額時は利用店名の文字列昇順とする。
- 金額は右寄せし、3桁区切りの日本円表示とする。
- 選択中の月別合計、集計対象件数、削除済み件数を結果表の近くに表示する。
- 集計行から、その利用者・利用店名に含まれる個別明細を明細管理画面で確認できるようにする。
- 月を切り替えた場合は、選択月の結果だけを表示し、別月の明細を混在させない。

### 9.5 個別明細管理

- 読み込んだ通常明細を1レコードにつき1行で表示する。
- 個別明細画面の上部にも利用者ごとの合計金額を表示する。
- 個別明細画面の利用者別合計には`集計対象`の明細だけを含め、`削除済み`の明細を含めない。
- 明細管理表には、選択欄、利用年月日、利用者、利用店名、金額、集計状態、操作を表示する。
- 個別明細の初期表示には`集計対象`と`削除済み`の両方を含め、除外操作後も対象明細を一覧から消さない。
- 個別明細は利用者、利用店名、集計状態で絞り込めるようにする。集計状態の初期値は`すべて`とする。
- 1件ずつの削除と、チェックボックスで選択した複数明細の一括削除に対応する。
- 削除対象が店舗別の集計行であるかのように誤解させず、削除は元CSVの個別明細単位で行う。
- 削除実行前に、対象月、件数、対象金額の合計を表示して確認を求める。
- MVPの削除は物理削除ではなく、明細の集計状態を`削除済み`に変更する操作とする。
- `削除済み`明細は薄い赤色の背景と赤色の状態表示に変更し、同じ個別明細一覧内に残す。
- 色だけに依存せず、`削除済み`という文字ラベルと`復元`操作も表示する。
- 削除直後は取り消し操作を表示し、削除済み一覧からも明細を復元できるようにする。
- 復元実行前に対象月と件数を表示し、復元後は集計状態を`集計対象`に戻す。
- 削除済み明細には`削除済み`という文字ラベルを表示し、色だけで状態を表現しない。
- 削除・復元操作は保存し、画面の再読み込み後も状態を維持する。
- 元CSVの利用者、利用店名、利用年月日、利用金額は削除・復元操作によって変更しない。

## 10. エラー・警告要件

### 10.1 集計を中止するエラー

- ファイルが選択されていない。
- CSVとして解析できない。
- 対応していない文字コードである。
- ファイルサイズまたは明細数が上限を超えている。
- 対象月が未入力または不正な形式である。
- 必須列がない、または同名の必須列が複数あり一意に決められない。
- 利用明細セクションを識別できない。
- 有効な通常明細が1件もない。
- 個別金額、店舗別合計、利用者別合計または全体合計が対応可能な整数範囲を超えている。
- macOSのApplication Support領域を利用できない。
- 保存容量不足等により、検証済みデータを完全に保存できない。

エラー表示には原因と利用者が取れる対処を含める。

### 10.2 該当行を除外して継続する警告

- 利用者が空欄である。
- 利用店名が空欄である。
- 利用金額が空欄である。
- 利用金額を整数として解釈できない。

警告には、タイトルやヘッダーを含めて1から数えたCSV上の論理レコード番号と理由を表示する。引用符内に改行がある場合も、物理的な改行位置ではなくCSVパーサーが認識したレコード番号を使用する。警告行を黙って除外してはならない。

### 10.3 保存・操作エラー

- 同一CSVの重複を検出した場合は保存せず、保存済みの対象月を案内する。
- 同じ対象月に別CSVが存在する場合は競合として表示し、利用者が置換または中止を選択するまで既存データを変更しない。
- CSV保存、月データの置換、明細の削除・復元は処理単位で完了させ、途中失敗時は操作前の状態を維持する。
- 削除・復元の保存に失敗した場合は集計結果だけを変更せず、操作が完了していないことを表示する。
- 操作エラーに個人名、店舗名、カード番号等のCSV内容を不必要に含めない。

## 11. 非機能要件

### 11.1 セキュリティ・プライバシー

- CSVは利用者のMac内だけで処理し、外部サーバーへ送信しない。
- 月別表示と明細操作のため、必要最小限の解析済みデータをmacOSのApplication Support領域に保存する。
- 保存対象は、対象月、利用年月日、利用者、利用店名、利用金額、明細ID、CSVレコード番号、集計状態、取込メタデータに限定する。
- 元のCSVファイル、カード番号、カード種別、支払い情報、摘要は保存しない。
- 保存データをサーバー、解析サービス、外部ストレージへ送信しない。
- 保存データは同一Macの利用者アカウント内だけで利用し、別端末とは同期しない。
- Application Support領域やmacOS利用者アカウントの削除によって保存データが失われる可能性を利用者に案内する。
- 個人名、カード番号、店舗名、金額をアプリのログへ出力しない。
- CSVセルの表示時は文字列としてエスケープし、スクリプトを実行させない。

### 11.2 性能

- 10MBまたは10万明細までのCSVを、一般的なPCで3秒以内を目標に処理する。
- 保存済み120か月分の月一覧を3秒以内に表示することを目標とする。
- 1万明細を超える明細管理表ではページングまたは仮想スクロールを使用し、画面操作を妨げないこと。
- 同じ入力と設定から常に同じ結果を得られること。

### 11.3 対応環境・利用性

- macOS 12以降のApple Silicon Macを対象とする。
- ファイル選択、読込、結果確認をキーボードだけでも操作できること。
- エラーや警告を色だけで区別せず、文章でも示すこと。
- 画面幅が狭い場合でも結果表の項目が欠落しないこと。

### 11.4 保守性

- CSV解析、セクション判定、正規化、集計、表示を分離する。
- 必須列名、ファイル上限、正規化規則、月別保存、明細状態管理を変更しやすい構成にする。
- 月データの保存・置換と明細の削除・復元には、処理途中の状態を残さないトランザクションを使用する。
- 個人名や店舗名をソースコードおよびテストデータへ固定値として埋め込まない。

## 12. 受入基準

### 12.1 添付CSVによる確認

1. UTF-8 BOM付きCSVを文字化けなく読み込める。
2. 10列の利用明細ヘッダーを検出できる。
3. 通常明細85件だけを集計対象として認識できる。
4. タイトル、ヘッダー、利用者別小計、総合計、キャッシングご返済明細を集計に含めない。
5. 2名の利用者を別々に集計できる。
6. 「利用者 × 利用店名」の35組に集約できる。
7. 複数明細を持つ11組がそれぞれ1行になり、元明細の利用金額合計と一致する。
8. 各利用者別合計が、その利用者の全通常明細の利用金額合計と一致する。
9. 全利用者の利用者別合計が、全通常明細の利用金額合計と一致する。
10. 結果表の列が「利用者」「利用店名」「金額」の3列である。
11. 読込時に指定した対象月へ保存され、画面再読み込み後も同じ月から表示できる。

### 12.2 月別管理と明細操作の確認

1. 異なる対象月で2つのCSVを保存し、月一覧に別々に表示できる。
2. 月を切り替えると、選択した月の集計と明細だけが表示される。
3. 同じ利用者・同じ利用店名が複数月に存在しても、月をまたいで合算されない。
4. 同一内容のCSVを再度読み込んでも、明細と金額が二重に追加されない。
5. 同じ対象月に異なるCSVを読み込むと、置換または中止を選択でき、中止時は既存データが変わらない。
6. 個別明細を1件削除すると、その明細だけが`削除済み`となり、該当店舗、利用者、対象月の合計が正しく再計算される。
7. 集計画面と個別明細画面の両方に、削除済み明細を除いた利用者別合計が表示される。
8. 明細を除外しても個別明細一覧から消えず、背景色と状態ラベルが`削除済み`表示に変わる。
9. 個別明細一覧の初期状態では、集計対象と削除済みの両方が表示される。
10. 複数明細を選択して一括削除でき、選択外の明細には影響しない。
11. 削除済み明細を復元すると、該当する各合計が削除前の値に戻る。
12. 削除・復元後に画面を再読み込みしても、集計状態と計算結果が維持される。
13. 削除・復元によって、元明細の利用者、利用店名、利用年月日、利用金額が変更されない。
14. 削除確認には対象月、対象件数、対象金額合計が表示される。
15. 保存または明細操作に失敗した場合、途中状態や部分的な集計結果が残らない。

### 12.3 追加テストデータによる確認

1. `利用金額`と`支払い金額`が異なる場合、`利用金額`を集計する。
2. 同一店舗名を異なる利用者が利用した場合、利用者ごとに別集計となる。
3. 前後空白だけが異なる店舗名は同一店舗として集計される。
4. 全角・半角、内部空白、大小文字が異なる店舗名は別店舗として扱われる。
5. マイナス金額が店舗別合計と利用者別合計に符号付きで反映される。
6. 必須列がないCSVでは、結果を表示せず具体的なエラーを表示する。
7. 不正な通常明細を含むCSVでは、正常行を集計し、除外行番号、理由、件数を警告する。
8. CSVセルにHTML、数式、命令文のような文字列があっても実行されず、安全な文字列として表示される。
9. 別CSVを再読込すると前回の結果とエラーが残らない。
10. 個別金額または加算途中の集計値が対応可能範囲を超えた場合、部分的な結果を表示せずエラーにする。

## 13. 初期実装で採用する前提

利用者から変更指示がない限り、MVPでは次を採用する。

| 論点 | 採用する前提 |
| --- | --- |
| アプリ形式 | macOSネイティブデスクトップアプリ |
| 集計する金額列 | `利用金額` |
| 店名の同一判定 | 前後空白除去後の完全一致 |
| 利用者の同一判定 | 前後空白除去後の完全一致 |
| 不正な通常明細 | 該当行を除外し、警告して正常行を集計 |
| 対応文字コード | UTF-8、UTF-8 BOM付き |
| 対象月 | ファイル名から候補を提示し、利用者が確認・指定 |
| ファイル数 | 1回につき1ファイル、1対象月につき1CSV |
| 同月の再取込 | 自動追記せず、置換または中止を選択 |
| 保存 | 必要最小限の解析済みデータをMac内のApplication Support領域に保存 |
| 明細削除 | 物理削除せず`削除済み`として集計から除外 |
| 復元 | 削除済み明細を元の内容のまま集計対象へ戻す |
| 保存期間 | アプリの保存データが利用者によって削除されるまで |

## 14. 実装開始前に変更可能な主な選択肢

- 集計金額を`利用金額`ではなく`支払い金額`にする。
- 全角・半角や決済接尾辞を含む店名の統合ルールを追加する。
- Shift_JIS（CP932）のCSVにも対応する。
- 複数月をまとめた期間集計、年次集計、月別比較を追加する。
- 同じ対象月に複数CSVを追記できるようにする。
- 明細内容の直接編集や手入力追加を可能にする。
- 削除済み明細の完全削除や、対象月全体の削除を追加する。
- 集計結果のCSVまたはExcel出力を追加する。
- 保存データのバックアップと復元を追加する。
- 複数端末間のクラウド同期やユーザー認証を追加する。
