# クレジット明細アプリ AI再構築仕様書

## 0. この資料の使い方

この文書は、現在のコードと設計を、別のAIや開発者が再実装するための引き継ぎ資料である。

- 「現在の実装」は、今回確認したコードに実際に存在する仕様。
- 「推奨仕様」は、不明点をAIが補うときの採用方針。現行仕様と異なるため、実装時は変更点として扱う。
- 既存の日本語要件定義は [要件定義書.md](要件定義書.md) である。本書はそれを実装レベルに落とした補足資料。

## 1. アプリの目的

macOS上で、月ごとのクレジットカードCSVをローカルに取り込む。請求対象月ごとに、利用者・利用店別の合計を表示し、個別明細を集計から除外・復元できるようにする。

### 必須方針

- データをサーバーや外部サービスに送信しない。
- 原CSV、カード番号、カード種別、支払い情報、摘要は保存しない。
- 金額は浮動小数ではなく`Int64`の整数。日本円として扱う。
- 対象月は`YYYY-MM`で内部保持し、画面では`YYYY年M月`と表示する。

## 2. 技術スタックと構成

### 採用する環境

- Swift 5.7以降
- macOS 12以降
- Swift Package Manager
- UI: SwiftUI、ファイル選択のためにAppKitとUniformTypeIdentifiersを使用
- ハッシュ: CryptoKitのSHA-256
- 永続化: FoundationのCodable + JSON

## 3. データモデル

### `EntryStatus`

```swift
enum EntryStatus: String, Codable, Hashable {
    case included   // 集計対象
    case excluded   // 集計から除外
}
```

### `CreditEntry`

1件の明細。`id` はUUIDで、同一月内で一意とする。除外・復元後も変えない。

| フィールド | 型 | 意味 |
|---|---|---|
| `id` | `UUID` | 明細ID |
| `statementMonth` | `String` | 対象月、`YYYY-MM` |
| `usageDate` | `String` | CSVのご利用年月日。空欄可 |
| `user` | `String` | 利用者 |
| `merchant` | `String` | 利用店名 |
| `amount` | `Int64` | 利用金額、円 |
| `sourceRecordNumber` | `Int` | 元CSVのレコード番号 |
| `status` | `EntryStatus` | 集計対象/除外済み |
| `excludedAt` | `Date?` | 除外操作時刻。復元時は`nil` |

### `StatementMonth`

1つの対象月の保存データ。`month` が一意キーで、`Identifiable.id` も`month` とする。

| フィールド | 意味 |
|---|---|
| `month` | 対象月、`YYYY-MM` |
| `sourceFileName` | 取り込んだCSVのファイル名 |
| `sourceHash` | CSVバイト列のSHA-256、重複取込防止に利用 |
| `importedAt` | 取込時刻 |
| `importWarnings` | 警告一覧 |
| `entries` | 明細一覧 |

派生値は永続化せず、明細から再計算する。

- `includedEntries`: `status == .included`
- `excludedEntries`: `status == .excluded`
- `importedTotal`: 全明細の合計
- `currentTotal`: 集計対象の合計
- `excludedTotal`: 除外済みの合計
- `merchantSummaries`: 利用者×利用店名ごとの`currentTotal`。利用者名、金額降順、店名順で並べる。
- `userTotals`: 利用者ごとの合計。すべての利用者を残し、全件除外でも`0円`で表示する。

### その他のモデル

- `ImportWarning`: `recordNumber` と警告文。
- `ImportResult`: 取込前の一時データ。元ファイル名、ハッシュ、対象月候補、明細、警告、取込合計を持つ。
- `ImportedEntry`: 保存前の明細。状態や`statementMonth` は持たない。
- `MerchantSummary` / `UserTotal`: 表示用の派生モデル。

## 4. CSV取込仕様

### 入力条件

- UTF-8 CSVのみ。UTF-8 BOMは取り除いて受け入れる。
- ファイルサイズ上限は10MB。取込明細数上限は100,000件。
- アプリのファイル選択は複数選択を許可しない。拡張子はファイル選択後に`.csv`を再確認する。

### ヘッダーとレコード

必須列は次の3列。ヘッダーはCSVの先頭行でなく、全行から最初に3列がすべてある行を探す。

- `名前`
- `利用店名`
- `利用金額`

任意列は`ご利用年月日`。存在する場合は利用日として保存し、存在しない場合は空文字にする。必須列の重複はエラーにする。フィールド前後の空白・改行は除去する。

### 金額解釈

- `1,000`、`-500`、`+500`、`¥1,000`、`￥1,000`を受け入れる。
- 整数でない値、小数、不明文字列は警告としてそのレコードだけ除外する。
- `Int64`の範囲に加え、安全上の上限を`9,007,199,254,740,991`（2^53-1）とする。レコード金額または合計が超えたらエラーで取込全体を中止する。

### 行の扱い

- 完全に空の行は無視。
- 名前・店名・金額のいずれかが空欄の不完全行は警告として除外。
- `名前`と`利用店名`の文字列から制御文字を除去する。ただしタブは残す。利用日は現在の実装では前後の空白除去のみ行う。
- 正常明細の後、名前・店名・利用日が空で他の値がある行は小計・合計などのフッターと判定して終了。
- 「キャッシングご返済明細」だけの文字がある行に到達したら終了。
- 引用符、カンマ、改行を含むCSVをパースする。引用符の不整合はエラー。

### 対象月候補

1. ファイル名から、連続する8桁の`YYYYMMDD`を探す。
2. 見つかったら`YYYY-MM`を候補にする。
3. 見つからなければ現在の年月を候補にする。
4. 候補は自動確定せず、保存前に利用者が確認・変更できる。

## 5. 保存とトランザクション

### ファイル形式

```text
~/Library/Application Support/CreditStatementApp/statements.json
```

`StatementRepository` が複数月の`[StatementMonth]`をシリアライズする。日付はISO 8601、JSONはソートキー付きインデント形式とする。書き込みは`.atomic`を指定する。

### 取込保存フロー

1. CSVを読み、全体を検証する。失敗時は既存データを変えない。
2. CSVのSHA-256が保存済みのどれかと一致する場合は重複として中止。
3. 同じ対象月がある場合、利用者が「置換」を確認するまで既存データを変えない。
4. 置換時は既存の明細と除外状態を新しいCSVで一括置換する。
5. 保存失敗時は操作前の`statements`に戻す。
6. 保存成功後、対象月を選択し、集計タブを表示する。

### 除外・復元フロー

- 対象のIDだけを更新する。
- 除外時は`status = .excluded` および`excludedAt = Date()`。
- 復元時は`status = .included` および`excludedAt = nil`。
- 保存失敗時は操作前に戻し、失敗をアラート表示。
- 状態変更後の合計は、保存済み明細から即時に再計算する。

## 6. 画面仕様

### 全体レイアウト

`WindowGroup`の最小サイズは`960 x 640`。上部ヘッダー、その下に左サイドバーとメイン領域を横並びで配置する。

#### ヘッダー

- アプリ名「クレジット明細」。
- 右側にCSV読込ボタン。読込中はProgressViewと「読込中」。
- `Command + O` でもCSV読込を開く。

#### 左サイドバー

- 幅は210pt。「保存済みの月」と月一覧を表示。
- 月は新しい月から降順。各行に表示月、現在の合計、集計対象件数。
- 選択月は青系背景と境界線。アプリ起動時は最新月。
- 月の行全体をクリック対象とするため、ラベルに`contentShape(RoundedRectangle(cornerRadius: 9))`を指定する。
- 未選択の月にマウスを乗せたときは`Color.primary.opacity(0.06)`のホバー背景を表示する。選択色を優先する。
- 下部に選択月の取込元ファイル名を2行まで表示する。

#### 月別ダッシュボード

- 「現在の合計」「集計対象」「集計から除外」のメトリック。
- セグメント切替: `集計` / `個別明細` / `削除済み`。

### 集計タブ

- 利用者別合計のカードを横スクロール表示。除外明細は含めない。
- 利用者×利用店別合計の表。利用者の小計行を付ける。明細行をクリックすると「個別明細」タブへ移動。
- 「金額の確認」パネルに、取込時合計、除外金額、現在の合計を表示する。
- 取込警告があると警告件数を表示する。

### 個別明細タブ

- 利用者別合計、店名・利用者検索、利用者フィルタ、状態フィルタ。
- 表示順は利用日の降順、同日は元CSVレコード番号の降順。
- 列は選択、利用日、利用者、利用店名、金額、状態、操作。
- 「除外」「復元」の単件操作と、選択した明細の一括除外。操作前に確認アラートを出す。

### 削除済みタブ

- 除外済みがなければ空状態。
- あれば除外明細の一覧と合計、一括・単件復元。

### CSV取込プレビュー

- モーダルシートの幅は680pt。警告がなければ410pt、あれば500pt。
- 対象年と月をPickerで変更可能。年の選択範囲は2000年から「現在年+2年」。
- 明細件数、利用者数、取込合計、警告件数を事前表示。
- 警告は最大で先頭4件を表示する。
- 保存時に同月データがあれば置換確認を表示する。置換時は除外状態をリセット。

## 7. AppModelの状態と遷移

### Published状態

```text
statements: [StatementMonth]
selectedMonthID: String?
selectedTab: DashboardTab
isShowingFileImporter: Bool
pendingImport: ImportResult?
alert: AppAlert?
isImporting: Bool
```

### 状態遷移

```text
起動
  -> statements.jsonを読込む
  -> 新しい月を選択、なければ空状態

CSV選択
  -> 読込/検証
  -> pendingImportをセット
  -> プレビューシート
  -> 対象月確認
  -> 保存
       -> 新規: 月を追加
       -> 同月: 置換確認 -> 置換または中止
       -> 同一CSV: 重複エラー

明細操作
  -> 確認アラート
  -> 状態更新
  -> JSON保存
  -> 集計を派生計算
```

## 8. エラーと警告

### 読込中止エラー

- UTF-8ではない
- CSVの引用符・改行が不正
- 必須列の欠落または重複
- 有効明細が0件
- 金額または合計が範囲外
- 拡張子が`.csv`ではない
- ファイルが10MB超、明細が10万件超

### 警告として取込継続するもの

- 名前・店名・金額の不完全行
- 金額を整数として解釈できない行

一般的な例外や保存失敗は、「データを変更していない」ことをメッセージに含める。

## 9. テスト方針

### 現在あるテスト

- 標準CSVの取込、フッター除外、合計、サマリ。
- 金額不正行の警告。
- カンマとエスケープ済み引用符。
- 不正CSVの失敗。
- JSON保存/読込と除外状態。
- 全明細除外時の利用者合計が0円で残ること。

### 再構築時に推奨する追加テスト

- 必須列重複、BOM、CRLF、引用符内改行。
- 金額の`¥`、負数、範囲外、合計オーバーフロー。
- 同一CSVの重複検出、同月置換のロールバック。
- 除外・復元保存失敗時のロールバック。
- `displayMonth("2026-07") == "2026年7月"`などの表示変換。
- 月選択行のクリック領域とホバー表示。

## 11. 推奨仕様と不明点の補完

別のAIが実装するときは、以下を既定の推奨として採用する。

1. データは元CSVではなく、必要最小限の解析済みデータだけを保存する。
2. 合計値はキャッシュせず、明細から派生させる。
3. 同一CSVの重複はハッシュで検出し、自動追記はしない。
4. 同月の異なるCSVは自動置換せず、必ず確認を求める。
5. 月選択はボタンとして実装し、キーボード操作とVoiceOverに配慮する。クリック領域は行全体とする。
6. 対象月は`YYYY-MM`の形式を壊さない。不正な日付や時刻は対象外とする。
7. 警告は全件を無理に画面表示せず、件数と先頭を表示する。詳細は将来の警告一覧で拡張する。
8. 保存失敗ではメモリ状態も元に戻す。中途的な合計だけを残さない。
9. ローカルJSONの破損時は空データとして静かに開始せず、データ未変更と復旧方法を表示する実装を推奨する。
10. UIを変更する場合も、「月一覧」「集計」「個別明細」「削除済み」の4つの利用者フローを維持する。

```text

アプリ名は「クレジット明細」。月ごとのクレジットカードCSVをローカル保存し、月別に利用者・利用店名・金額を集計する。

必須機能:
- UTF-8 CSV、BOM対応、必須列は「名前」「利用店名」「利用金額」。任意列は「ご利用年月日」。
- カンマ・引用符・改行を含むCSVを正しく解析する。
- 金額は日本円のInt64、表示は千桁区切りと「円」。
- ファイル名のYYYYMMDDから対象月を提案し、保存前に変更できるようにする。
- 同一CSVはSHA-256で重複防止、同月の異なるCSVは確認後の置換。
- 明細の除外・復元、ローカルJSONのアトミック保存。集計は明細から再計算。
- 画面はヘッダー、月サイドバー、集計、個別明細、削除済み、CSVプレビュー。
- 月サイドバーは行全体がクリック可能、ホバー中は薄い背景を表示。
- 不明点は上記の推奨仕様を採用し、実装後に`swift test`とリリースビルドを実行せよ。

元の設計と保存フォーマットを崩さず、変更した点はテストと文書に残せ。
```
