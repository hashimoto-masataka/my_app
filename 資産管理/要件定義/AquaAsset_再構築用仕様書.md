# AquaAsset 再構築用仕様書

## 1. 文書の目的

本書は、現在の AquaAsset（夫婦向け・ローカル完結型の資産管理デスクトップアプリ）を、別のAIまたは開発者が同等の画面・挙動で再作成するための実装引き継ぎ資料である。記載内容は、現行コードで実装済みの仕様を正とし、コードに明示されていない事項は再構築時の推奨値として定義する。

## 2. プロダクト概要

- アプリ名: AquaAsset
- 目的: 夫婦それぞれの資産と共有資産、収入、固定費、月次履歴を一元管理する。
- 対象: 家庭内の資産状況を安全に把握したい個人・夫婦。
- 動作形態: Tauri 2 のデスクトップアプリ。バックエンドサーバーや外部APIは使用しない。
- 保存方針: 端末内の `localStorage` に保存。金融機関・広告・分析サービスへデータ送信しない。
- 通貨: 日本円。表示は `¥` と日本語ロケールの3桁区切り。

## 3. 技術構成

| 層 | 採用技術 |
|---|---|
| デスクトップ | Tauri 2 / Rust |
| UI | React + TypeScript |
| ビルド | Vite、TypeScript (`tsc`) |
| アイコン | `lucide-react` |
| グラフ | 依存ライブラリなし。SVG折れ線、CSSドーナツ、CSS棒グラフを自前描画 |
| 永続化 | `localStorage`（キーは後述） |
| パッケージ | macOS `.app`（Tauri bundle） |

## 4. 画面とナビゲーション

サイドバー固定、右側にメインコンテンツを表示する2カラム構成。ナビゲーション項目は次の順序とする。

1. ダッシュボード
2. 資産一覧
3. 収支管理
4. 推移・履歴
5. 設定

### 4.1 ダッシュボード

ヘッダーに「ダッシュボード」と説明文を表示し、画面上部に以下を配置する。

- 年選択: 利用可能な履歴年を降順で表示。左右矢印でも切替。
- スコープ切替: `世帯全体 / 夫 / 妻`。選択したスコープはグラフ、ポートフォリオ、主な資産に反映。
- 夫婦サマリー: 世帯総資産、夫、妻の金額・構成比。共有資産は持分按分。
- ポートフォリオ配分: カテゴリ別金額と割合をドーナツチャートで表示。「詳細を見る」で資産一覧へ遷移。
- 資産推移: `1ヶ月 / 3ヶ月 / 6ヶ月 / 1年 / 全期間`。年と期間に応じたSVGネオン折れ線、面グラデーション、ツールチップを表示。
- 主な資産: スコープの金額が大きい順に最大6件。カテゴリ、名称、所有者、評価額、構成比、前月比を表示。

### 4.2 資産一覧

画面上部に `全体 / 夫 / 妻` の切替を置く。選択スコープに応じて、次のすべてを再計算する。

- カテゴリサマリー（預金、国内株式、米国株式、暗号資産、投資信託、その他）
- カテゴリ件数と金額
- 一覧の評価額列
- 表示中件数、合計金額、構成比

共有資産は夫の持分を `husbandShare`%、妻の持分を `100 - husbandShare`% とする。対象者の按分額が0円の行は、そのスコープでは表示しない。

追加の操作:

- 資産名検索
- カテゴリタブ絞り込み
- 所有者絞り込み（すべて / 夫 / 妻 / 共有）
- 資産追加、編集、削除

資産追加はカテゴリ選択画面を経由し、預金・国内株式・米国株式・投資信託・暗号資産・その他の入力画面を分ける。

### 4.3 資産追加フォーム

共通入力項目は資産名、保有者、評価額。共有を選んだ場合は夫の持分を5%刻みのスライダーで入力する。

- 預金: 金融機関・口座名、現在の評価額
- 国内株式: 銘柄名、証券コード、証券会社、保有数量、現在値
- 米国株式: 銘柄名、証券コード、証券会社、保有数量、現在値
- 投資信託: ファンド名、商品コード、証券会社、保有口数、基準価額
- 暗号資産: 通貨名、シンボル、取引所、保有数量、現在価格
- その他: 資産名、現在の評価額

株式等の評価額は `保有数量 × 現在価格` で自動計算する。登録時の `previous` は現在額と同値、シンボル未入力時は名称の先頭文字を使用する。

### 4.4 収支管理

給料・収入と固定費を左右2列で管理する。

- サマリー: 世帯手取り、固定費、毎月の余力
- 収入: 項目名、所有者、月額
- 固定費: 項目名、所有者、月額、支払日
- 追加モーダルと削除操作
- 貯蓄率 = `(収入合計 - 固定費合計) / 収入合計 × 100`

### 4.5 推移・履歴

- 年選択
- 夫・妻を横並びで比較する月別棒グラフ
- 月別パフォーマンス表（対象月、総資産、増減額、増減率）
- 「過去データを登録」モーダル: 対象月、夫の資産額、妻の資産額
- 同じ月を保存した場合は既存レコードを置換

### 4.6 設定

- パスコードロックのON/OFF（4桁以上を推奨）
- パスコード変更
- JSONバックアップ作成・ファイル復元
- テーマ: ダーク / ライト / システム
- アクセントカラー: ティール、ブルー、バイオレット、ピンク系

## 5. データモデル

現行フロントエンドの型は次のとおり。

```ts
type Category = '預金' | '国内株式' | '米国株式' | '暗号資産' | '投資信託' | 'その他';
type Owner = '夫' | '妻' | '共有';
type Asset = {
  id: number;
  name: string;
  category: Category;
  amount: number;
  previous: number;
  symbol: string;
  owner: Owner;
  husbandShare: number; // 0〜100。共有以外は夫=100、妻=0
};
type HistoryRecord = { month: string; husband: number; wife: number }; // YYYY-MM
type CashflowItem = {
  id: number;
  type: 'income' | 'expense';
  name: string;
  owner: Owner;
  amount: number;
  day?: number;
};
type Page = 'dashboard' | 'assets' | 'income' | 'history' | 'settings';
```

### 5.1 持分計算

```ts
ownerAmount(asset, '夫') = asset.amount * asset.husbandShare / 100
ownerAmount(asset, '妻') = asset.amount * (100 - asset.husbandShare) / 100
```

`ownerPrevious` も `previous` に同じ係数を掛ける。世帯全体は按分せず `amount` をそのまま使う。

### 5.2 永続化キー

| キー | 内容 |
|---|---|
| `aqua-assets` | `Asset[]` |
| `aqua-history` | `HistoryRecord[]` |
| `aqua-cashflow` | `CashflowItem[]` |
| `aqua-settings` | `{ lock, passcode, theme, accent }` |

初回起動時は `src/data.ts` のサンプルデータを使用する。JSONバックアップは `version`, `exportedAt`, `assets`, `history`, `cashflow`, `settings` を含む。

## 7. UI/ビジュアル仕様

- 基本はダーク、紺〜青緑の背景、ティールのネオンアクセント。
- サイドバーは固定幅約224px。アクティブ項目はティール〜青のグラデーションと発光。
- メインは最小幅1080pxを想定。カードは濃紺のグラデーション、薄い青緑の境界線、角丸11px前後。
- 夫はブルー、妻はバイオレット、共有はティールで識別。
- 金額は大きく、補助情報は低彩度のグレー。増加は緑、減少は赤。
- 画面遷移、カード表示、折れ線描画、金額変更に短いアニメーションを付ける。
- ライトテーマでは白いカードと淡い緑灰色の背景に切り替える。

## 9. 主要な受け入れ条件

1. アプリ起動後、サンプル資産を含むダッシュボードが表示される。
2. 「詳細を見る」で資産一覧へ遷移する。
3. 資産一覧の「夫」を押すと、夫所有資産と共有資産の夫持分だけが表示される。
4. 国内株式・米国株式の金額が、全体・夫・妻で正しく変わる。
5. 資産を追加、編集、削除して再起動しても内容が保持される。
6. 同じ月の履歴を再登録すると、その月が更新される。
7. 収入・固定費の追加と削除、余力・貯蓄率計算が動作する。
8. 設定変更、バックアップ、復元、パスコードロックが動作する。
9. 外部ネットワークなしで主要機能を利用できる。
10. macOSではアイコンから `.app` を起動できる。

## 10. 実行・ビルド手順

```bash
npm install
npm run dev          # ブラウザ開発
npm run desktop:dev  # Tauri開発ウィンドウ
npm run build        # 型チェック + Vite本番ビルド
npm run desktop:build # macOS AquaAsset.appを生成
```

生成先は `src-tauri/target/release/bundle/macos/AquaAsset.app`。配布用に署名する場合は、環境に応じて ad-hoc 署名後、プロジェクト直下へコピーする。

## 11. 推奨する未実装・将来拡張

現行仕様にない事項は、次の方針を推奨する。

- 本番保存: `localStorage` から暗号化SQLiteまたはTauri Storeへ移行。
- パスコード: 平文保存を避け、OSキーチェーンまたはソルト付きハッシュを利用。
- 入力検証: 金額の負数禁止、上限値、必須項目、重複ID、履歴月の妥当性を検証。
- 履歴精度: 資産単位の月次スナップショットを追加し、カテゴリ別・所有者別の過去推移を再現可能にする。
- バックアップ: 復元前の確認ダイアログ、スキーマバージョンアップ、破損時の自動バックアップを追加。
- アクセシビリティ: キーボード操作、フォーカス表示、色だけに依存しない所有者表示、画面読み上げラベルを追加。
- レスポンシブ: 最小幅未満では横スクロールではなく、カード縦積みへ切り替える。
- 市場価格連携: 外部APIは初期状態では導入せず、導入時はユーザー同意・取得日時・レート制限・障害時の手入力維持を必須とする。

## 12. 再構築時の実装方針

1. まず `types.ts` と `data.ts` を作り、持分計算と表示フォーマットを単体テストする。
2. `App.tsx` にページ状態、localStorage同期、モーダル状態を実装する。
3. `components.tsx` でレイアウトを固定し、各画面を独立コンポーネント化する。
4. 最初に機能を完成させ、その後CSS上書きでサンプル画面の寸法・色・発光を合わせる。
5. ダッシュボードと資産一覧について、全体・夫・妻の3パターンを実データで目視確認する。
6. `npm run build`、Tauriビルド、起動確認の順に検証する。
